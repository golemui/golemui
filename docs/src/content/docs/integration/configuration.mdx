## Property reference

### Required

#### `formDef`

<DslTabs>
  <Fragment slot="dx">
    A **Programmatic** array of `gui.*` shortcuts. Composed with `gui.inputs.*`, `gui.layouts.*`, `gui.actions.*`, `gui.displays.*` and resolved through the DX pipeline at render time.

    ```ts
    import { gui } from '@golemui/gui-shared';

    const formDef = [
      gui.inputs.textInput('name', { label: 'Name' }),
      gui.actions.submitButton({ label: 'Submit' }),
    ];
    ```

    Wire it to the form component:

### Selectors and engine config

<DslTabs>
  <Fragment slot="dx">

The Programmatic API has two dedicated wiring objects — `formSelectors` for behavior decorators, and `formConfig` for engine knobs. Both are typed and composable.

#### `formSelectors`

GSL selector decorators that apply by widget type, tag, or uid. Built with `gui.selectors.*` and resolved against your `formDef` array at render time. See [Selectors](/form-definition/selectors/).

```ts
import { gui } from '@golemui/gui-shared';

const formSelectors = [
  gui.selectors.inputs({ suppressAutomaticPlaceholders: true }),
  gui.selectors.tag('identity').inputs({ autocomplete: 'off' }),
];
```

Wire it alongside `formDef`:

<IntegrationTabs>
  <Fragment slot="react">
    ```tsx
    <React.FormComponent
      formDef={formDef}
      formSelectors={formSelectors}
      data={{}}
    />
    ```
  </Fragment>
  <Fragment slot="angular">
    ```ts
    // template:
    // <gui-form [formDef]="formDef" [formSelectors]="formSelectors" [data]="formData"></gui-form>
    protected formDef = formDef;
    protected formSelectors = formSelectors;
    ```
  </Fragment>
  <Fragment slot="lit">
    ```ts
    html`<gui-form
      .formDef=${formDef}
      .formSelectors=${formSelectors}
      .data=${{}}
    ></gui-form>`;
    ```
  </Fragment>
</IntegrationTabs>

#### `formConfig`

DX engine wiring container. Holds `widgetLoaders`, `itemRenderers`, `dependencies`, `validateOn`, `customValidators`, `states`, `suppressAutomaticSubmit`, `suppressAutomaticStack`. The Programmatic API treats `formConfig` as the single home for all of these knobs.

```ts
const formConfig = {
  widgetLoaders: React.widgetLoaders,
  itemRenderers: { countryRenderer },
  dependencies: { markdown: { parse: snarkdown } },
  validateOn: 'eager',
  states: {
    hasDiscount: '$form.hasDiscountCode === true',
  },
  suppressAutomaticSubmit: true,
};
```

Wire it alongside `formDef`:

#### Putting it all together

A complete component skeleton wiring `formDef`, `formSelectors`, and `formConfig` together — copy this as the starting shape for your own form:

<IntegrationTabs>
  <Fragment slot="react">
    ```tsx
    import { gui } from '@golemui/gui-shared';
    import * as React from '@golemui/gui-react';

    const formDef = [
      gui.inputs.textInput('name', { label: 'Name' }),
      gui.actions.submitButton({ label: 'Submit' }),
    ];
    const formSelectors = [
      gui.selectors.inputs({ suppressAutomaticPlaceholders: true }),
    ];
    const formConfig = {
      widgetLoaders: React.widgetLoaders,
      validateOn: 'eager',
    };

    export function MyForm() {
      return (
        <React.FormComponent
          formDef={formDef}
          formSelectors={formSelectors}
          formConfig={formConfig}
          data={{}}
        />
      );
    }
    ```
  </Fragment>
  <Fragment slot="angular">
    ```ts
    import { Component } from '@angular/core';
    import { CommonModule } from '@angular/common';
    import { gui } from '@golemui/gui-shared';
    import * as Angular from '@golemui/gui-angular';

    @Component({
      imports: [CommonModule, Angular.FormComponent],
      selector: 'app-my-form',
      template: `<gui-form
        [formDef]="formDef"
        [formSelectors]="formSelectors"
        [formConfig]="formConfig"
        [data]="formData"
      ></gui-form>`,

      protected formDef = [
        gui.inputs.textInput('name', { label: 'Name' }),
        gui.actions.submitButton({ label: 'Submit' }),

        gui.selectors.inputs({ suppressAutomaticPlaceholders: true }),
      ];
      protected formConfig = {
        widgetLoaders: Angular.widgetLoaders,
        validateOn: 'eager' as const,
      };
      protected formData = {};
    }
    ```
  </Fragment>
  <Fragment slot="lit">

    ```ts
    }
    ```

  <Fragment slot="json">

The JSON path expresses the same behaviors **inline on the form itself** and **as standalone component props** — there's no `formSelectors` or `formConfig` wrapper to compose. Each path has its own ergonomics:

- **Inline on the JSON** — `"states"` at the form root, `"label.someState"` suffixes on widget props for per-state overrides, the `validator` block on each input. The form ships with its behavior baked in, which is convenient when the form definition lives in a CMS or backend.
- **Standalone component props** — `customWidgetLoaders`, `itemRenderers`, `customValidators`, `dependencies`, `validateOn`. These stay in your application code, which keeps secrets, framework imports, and platform-specific renderers out of the form payload.

A typical JSON form with state-driven behavior:

```json
{
  "states": {
    "hasDiscount": "$form.hasDiscountCode === true"
  },
  "form": [
    {
      "kind": "input", "type": "textinput", "path": "discountCode",
      "label": "Discount code",
      "label.hasDiscount": "Your discount code",
      "include": { "in": ["hasDiscount"] }
    }
  ]
}
```

#### Putting it all together

A complete component skeleton wiring a JSON `formDef` plus the standalone engine-wiring props — copy this as the starting shape for your own JSON-driven form. The widget loader, renderer, and validator below are the same shapes used in the Programmatic example; only the wiring differs.

<IntegrationTabs>
  <Fragment slot="react">
    ```tsx

    import { CountryRenderer } from './renderers/CountryRenderer';
    import { allowedNames } from './validators/allowed-names';

    const itemRenderers = { countryRenderer: CountryRenderer };
    const customValidators = { allowedNames };

    export function MyForm() {
      return (
        <React.FormComponent
          formDef={formDef}
          data={{}}
          customWidgetLoaders={customWidgetLoaders}
          itemRenderers={itemRenderers}
          customValidators={customValidators}
          validateOn="eager"
        />

    }
    ```

### Engine wiring

The next group of properties wires the engine — widget loaders, item renderers, custom validators, validation timing, dependencies, and states. They mean exactly the same thing in both paths; what differs is **where** you put them.

<DslTabs>
  <Fragment slot="dx">
    With the Programmatic API, the typical home for these knobs is **`formConfig`** — a single typed object you pass to the form component. The standalone props (`customWidgetLoaders`, `itemRenderers`, etc.) still work and merge with whatever you put in `formConfig`, which is handy when you want to keep environment-specific bits out of the resolved form.
  </Fragment>
  <Fragment slot="json">
    With the JSON path, each knob is a **standalone component prop** — `customWidgetLoaders`, `itemRenderers`, `customValidators`, `validateOn`, `dependencies`. They live in your application code rather than in the form payload, which is exactly what you want when the JSON itself is loaded from a CMS, an API, or a backend.
  </Fragment>
</DslTabs>

#### Custom validators

Map of validator name → schema factory. Referenced from a widget's `validator: { type: 'custom', <name>: <config> }`. The factory follows the `CustomValidatorSchemaFn` interface and returns a schema (typically a Zod check):

```ts
import * as Core from '@golemui/core';
import * as z from 'zod';

export const allowedNames: Core.CustomValidatorSchemaFn = (names: string[]) =>
  z.string().check(
    z.superRefine((val, ctx) => {
      if (val && names.includes(val) === false) {
        ctx.addIssue({
          code: 'custom',
          message: `Name "${val}" not in ${names.map((n) => `"${n}"`).join(', ')}`,
          input: val,
        });
      }
    }),
  );
```

#### Validation timing

When validation runs. Accepts a single mode or an array combining the latter three:

```ts
type ValidateOn =
  | 'eager'
  | 'change'
  | 'blur'
  | 'submit'
  | ('change' | 'blur' | 'submit')[];
```

| Mode       | Triggers when                                              |
| ---------- | ---------------------------------------------------------- |
| `'change'` | The user changes the field value                           |
| `'blur'`   | The user leaves the field                                  |
| `'submit'` | A `submit` event is emitted (all fields are touched first) |
| `'eager'`  | Any of the above happens (default)                         |

#### Dependencies

Today, the only built-in widgets that need a dependency are [Markdown](/widgets-reference/input-fields/markdown/) and [Markdown Text](/widgets-reference/display-fields/markdown-text/) — both expect a `markdown.parse` function for live preview rendering.

<Aside type="tip">
You can use any markdown parser that exposes a `(markdown: string) => string` function, such as [snarkdown](https://github.com/developit/snarkdown), [marked](https://github.com/markedjs/marked), or [micromark](https://github.com/micromark/micromark).
</Aside>

### Form Callbacks

#### `formEvent`

Fired when a widget fires a wired event (`onClick`, `onChange`, `onLoad`, `onFilter`, `onBlur`). Payload: `{ name, data, detail }`. See [Features / Form Events](/features/events/).

<IntegrationTabs>
  <Fragment slot="react">
    ```tsx
    import * as Core from '@golemui/core';

    function handleFormEvent(event: Core.FormEvent) {
      if (event.name === 'submit') {
        console.log('Submit:', event.data);
      }
    }

    <React.FormComponent
      formDef={formDef}
      data={formData}
      formEvent={handleFormEvent}
    />
    ```
  </Fragment>
  <Fragment slot="angular">
    ```ts
    import * as Core from '@golemui/core';

    // template:
    // <gui-form [formDef]="formDef" [data]="formData" (formEvent)="onFormEvent($event)"></gui-form>
    protected onFormEvent(event: Core.FormEvent) {
      if (event.name === 'submit') {
        console.log('Submit:', event.data);
      }
    }
    ```
  </Fragment>
  <Fragment slot="lit">
    ```ts
    import * as Core from '@golemui/core';

    onFormEvent(event: Core.FormEvent) {
    ```

  </Fragment>
</IntegrationTabs>
