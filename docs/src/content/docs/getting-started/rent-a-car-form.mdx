In this chapter you'll declare every input the form needs, in a sensible order, with no logic yet. The form ends up rendering all the pieces but doesn't react to anything — that's what the next chapters add.

## Layout convention

GolemUI ships two layouts that cover most needs:

<DslTabs>
  <Fragment slot="dx">
    - **`gui.layouts.grid`** for **rows**. Subgrid alignment keeps labels, inputs, and validation messages aligned across all children in a row.
    - **`gui.layouts.flex`** for **columns**. Lighter, more flexible for vertical stacks.
  </Fragment>
  <Fragment slot="json">
    - **`{ "kind": "layout", "type": "grid" }`** for **rows**. Subgrid alignment keeps labels, inputs, and validation messages aligned across all children in a row.
    - **`{ "kind": "layout", "type": "flex" }`** for **columns**. Lighter, more flexible for vertical stacks.
  </Fragment>
</DslTabs>

The top-level form definition is implicitly stacked vertically (the engine adds an auto-stack — see [Sensible defaults](/form-definition/selectors/sensible-defaults/)), so we only need a `grid` when we want fields side-by-side.
